# ifa-support

> 本仓同时是 Odyss 本地化组件的**编排管理仓**：全套管理规范见 [`MANAGEMENT.md`](MANAGEMENT.md)，全栈本地化 SOP（一套拉起）见 [`local-stack/`](local-stack/README.md)，演示现场网络方案（展会拓扑与公司内模拟）见 [`NETWORK.md`](NETWORK.md)。以下为 da3-web 演示服务说明（服务名沿用历史称谓，DA3 模型已于 2026-08-25 退役）。

5090 服务器上跑在 `0.0.0.0:8060` 的运维/演示 Web 服务（原目录 `~/da3-web`），单文件 FastAPI 应用，纯服务端渲染、零前端构建。（「5090」沿用主机称谓；2026-08-24 起双卡：**RTX Pro 6000 Blackwell 96GB（独占 vLLM）+ RTX 5090 32GB（SAM3）**，全文不改名。DA3 已于 2026-08-25 退役。）

- **`/` 根路径**：直接跳 `/experience`（主链路展示页）；调试页从 `/panel` 顶部导航进。
- **`/experience` 浅体验区展示页**：IFA 展台品牌化全屏 UI（Figma「IFA 专项 · 浅体验区」实现）。全屏背景为硬件深度的两种来源（默认「设备深度图」=mini 端伪彩深度帧，可切「设备点云」=硬件真深度反投影彩色点云 GLB；任何情况不展示设备 RGB 原图，产物未就绪时保持黑场。DA3/SAM3 派生的四种点云来源已于 2026-08-17 去冗余下线）。「设备深度图」来源（仅 G335 等带硬件深度的相机）直接展示 mini 端伪彩深度帧，抽屉配全套渲染调节（色彩映射/方向/量程或自动分位/gamma/均衡/填洞/时空域滤波/描边/等值线/无效点色/JPEG 质量/深度帧率——经 `device-config` 下发到推流端渲染，约 2~4s 生效）与本页即时显示调节（CSS 亮度/对比度/饱和/色相/反色/模糊/透明度/缩放/镜像/旋转/像素化）；另有「点云化样式」区（对图片类背景通用）：canvas 像素格化 + mask 圆点镂空，保留原色彩把画面离散成等距圆点（开关/点距/圆径占比/背景色，浏览器端即时生效）。右下「调节」抽屉顶部是**识别触发（主链路直传 VLM）**——按可调间隔（默认 0.5s）取当前设备的最新 RGB 帧做识别，两种口径共用同一条触发线程：**开**=整帧直送 Qwen VLM 问画面里有什么食物；**关**=同一帧先过 SAM3（生产词表 + food 词，直接跑彩色帧），认出食物/饮品才带框送 VLM（SAM3 只当前置门，命中后照样出识别卡，省画面空时的 VLM 调用）。另可调并发上限（1=串行·最新优先，调大才真按间隔多路齐发），配置走 `/api/recog/direct/config` 落盘全局共享，详见 `docs/sam3-usage-map.md`；其下是**数据源帧率**（per-device：RGB 推帧 fps + Astra 类设备的点云直传间隔，写 `/api/frame/device-config`，推流端轮询生效，两台摄像机各调各的），其下点渲染样式区仅 GLB 类来源（设备点云）展示；右侧状态区在「Place your food here」待机态与识别成功态（浅色玻璃卡片：名称 / 英文短描述 / 卡路里 / 蛋白·碳水·脂肪 / Good·Neutral·Bad 健康分级，营养数字按画面可见份量估算）间切换；另有流水视图（临时按钮进入）展示当日识别记录。品牌字体（ABC Arizona Serif / Seabirds，trial 版）在 `static/fonts/`，经 `/static` 提供。`?demo=1` 为无后端目检模式。
- **`/panel`（已下线）**：原 DA3 扩展面板（上传图出深度 / 点云 / 网格）已随 **DA3 于 2026-08-25 整体退役**删除，路由保留一页去向提示。设备帧与全部调节在 `/experience` 右下「调节」抽屉；SAM3 调优在 `/sam3tune`。

### 参考食物库（2026-08-18 起）

展台要摆的那几种食物可以先在控制面「参考食物库」页签录进来（实物图 1~2 张 + 那一份的营养
+ 英文描述）。识别时这批图会被钉在每轮 VLM 请求的**最前面**当「参考清单」，模型只回答
「桌上那个是不是清单里第几项」（`ref_id`），命中就由服务端查库回填名称/描述/营养/分级——
模型编的数字一律丢弃。没命中的照旧走自由识别，未录入的食物不受影响。

- **上限**：最多 20 种、每种 2 张图；参考图边长可选 256/320/384/448/512（默认 384，320 实测偏糊）。
  每张的视觉 token ≈ (边长/32)²（该模型 patch 16 + merge 2，一个 token 覆盖 32×32 像素），
  控制面顶部常驻显示「几种 / 几张 / 约多少 token」的实数。
- **前缀稳定 = 能命中 KV 缓存**：参考图在录入时就按当前档位规范化并落盘缓存，之后每轮复用
  同一份文件字节；顺序恒按 id 升序；每轮会变的东西（当前帧、去重候选、上次选中）一律留在
  后面那条消息里。现网 vLLM（5090 本机裸进程 `:8000`，`enable_prefix_caching=True`）据此可以把这段前缀的
  prefill 省掉——2026-08-18 实测改造前整体命中率只有 1.34%，因为当时第一张图就是每 0.5s
  变一次的当前画面。换档位或增删条目会 `version+1`，只有换版那一轮 miss。
- **防幻觉**：参考图烧了 `REFERENCE - NOT CURRENT FRAME` 横幅，prompt 里另有明令，服务端还要求
  模型给出「在当前画面哪个位置看到它」的证据（`ref_evidence`），说不出位置的命中一律丢弃——
  实测过画面空无一物时模型照着参考图报 Snickers，参考区提到最前面会放大这个风险。
- **去重也跟着简化**：命中同一 `ref_id` 且在活跃窗口内直接并卡，不再走 `B1C1S1V1` 证据码那五道闸门
  （那套只留给未命中项）。展示端命中卡右上角有一个极轻的小圆点表示「内容来自参考库」。

### 识别 prompt 的排布与去重口径（2026-08-18 重排）

线上出现过「桌上是一袋金黄包装的焦糖爆米花，模型反复报 Orange / Clementine」，
且一张卡自我确认了 252 次（合并史清一色「四项全一致 + high」）。根因不在文案措辞，
在结构，因此这次动的是结构：

- **参考图从整帧改成物体特写**（`recog_match.pick_ref_box` 按本轮最大检测框取框、外扩 1.25×，
  从原图裁、缩到长边 256）。整帧参考图与当前画面是同一台相机同一张桌子，九成像素相同，
  「品牌/颜色/形状/容器四项一致」是**客观事实**——证据码必然全 1，去重形同虚设。
  顺带把参考图的视觉 token 从每张约 900 降到 100 上下（8 张整帧曾占掉七成以上视觉预算）。
- **content 重排**：`[固定段] → 任务二清单 → 逐个「标签+参考图」→ [CURRENT FRAME] → 带框图 → 收尾`。
  每张图前面都有一行方括号标签把它命名（旧版靠「图1/图2/图3」数序数，多图时对不齐），
  **当前画面排在所有参考图之后**，成为离生成最近的那张图。
- **任务一强制「先描述、后命名」**：先写 `seen`（颜色/形状/包装上读到的文字/位置），
  `name` 必须被 `seen` 支持；并写死「包装的颜色不是内容物的颜色」——那正是金黄包装被叫成 Orange 的路径。
- **粘性规则从「要求确认」改成「独立复核」**：旧文案「只要它仍在画面里就继续选它」把开放问题
  偷换成是非题，VLM 的 yes-bias 会让一次误报一路确认下去。
- **两道新闸门**（`recog_match.check_self_evidence`，纯格式、零语义）：说不出 `seen`、
  说不出与候选的差别（`diff` 为空/太短/是套话）、或证据码 B 位填 1 却没照抄出任何包装文字
  （`cur_text` 为空）——三者一律拒合并。让「填 1」不再零成本。
- **候选池**：数量 8 → 3、同名归一化去重、卡片绝对存活上限 `RECOG_CARD_MAX_LIFE`(120s，
  合并刷新的是 `last_ts`，`first_ts` 不刷新)，以及**强制复检轮**：某卡每被合并 15 次就有一轮
  把它从候选剔除、并关闭粘性，让模型在无提示下重看一次；仍报同名才回收合并。

### prompt 与模型产出改英文（2026-08-25）

展台面向的是德国观众与英文展示界面，而 `seen` / `diff` / `ref_evidence` 这些自由文本
过去是中文，控制面之外没人看得懂。这一版把**发给模型的每一个字符串**（固定段、参考区、
任务零、候选清单、图片标签、收尾复读）与**模型要吐回来的每一个值**都换成英文：

- 图片标签由 `【当前画面】/【当前画面 · 检测框版】/【历史参考图 · 候选[i]】` 换成
  `[CURRENT FRAME] / [CURRENT FRAME · BOXED] / [PAST REFERENCE · CANDIDATE[i]]`；
- `type` 让模型答 `food` / `drink`，服务端 `_parse_recog` 与 `foodref.normalize_item`
  照旧归一回内部枚举「食物 / 液体」——库、卡片、前端 `typeCls` 读的仍是中文值，不受影响；
- **德文描述 `description_de` 整条链路删除**：prompt 不再要、解析不再产、卡片不再带、
  旧调试面不再展示，参考库也不再存（运营那侧本来就没有录入口，字段一直是空的）；
- `seen` / `cur_text` / `diff` 的截断上限同步放宽（200 / 60 / 100 字符），同一句话英文比
  中文长 2~3 倍，沿用旧口径会把句子从中间切断；`recog_match.DIFF_BLANKS` 的套话清单换成
  英文并改为大小写不敏感匹配，`DIFF_MIN_LEN` 从 6 提到 15。
- **参考清单只给英文名**：`item_label` 用 `name_en`（留空回落 `name`），`task_zero` 明令「命中时照抄
  清单里的英文名」——清单名是命中后被一字不差抄进 `name` 的东西，给中文名模型就照抄中文，
  那是产出里最后一处会冒中文的地方。控制面录入表单同期把「英文名」字段加了回来。
  条目的 `look`（外观描述）照旧原样进清单，中文也不动：它是判同线索、不进任何输出字段。
- 不变的是**服务端这一侧**：日志、控制面文案、证据码解码文本（`品牌与包装一致；…`）仍是中文，
  superadmin 的识别日志面板不用跟着改。

> **电子秤不在本服务**：四通道食物秤（净重 / 毛重、软件去皮）与桌边分组由独立的 dx-backend 提供（`0.0.0.0:8070`，见 `dx_backend.py`），8060 已无 `/weight` 与 `/api/weights`。秤的地址与网络前提见 [`NETWORK.md`](NETWORK.md)。

> **GPU 占用（2026-08-25 起）**：DA3 模型已退役，本服务常态不再加载任何模型、不占 GPU（识别调本机 vLLM:8000、分割调 SAM3:8013，均为独立服务）。systemd unit 仍按 UUID 钉在 GPU1=RTX 5090 作兜底，绝不挤占 GPU0 上独占的 vLLM。

## 运行

```bash
./run.sh
# 等价于：
# python -m uvicorn app:app --host 0.0.0.0 --port 8060
```

局域网内访问 `http://<5090局域网IP>:8060`。

## 部署（git 部署源模式）

5090 上的运行目录 `~/da3-web` 是本仓的 checkout，**只 pull、不 commit/push**（用只读 deploy key）。开发流程：

```
本地改代码 → push 到 GitHub → 登录 5090 → cd ~/da3-web && ./deploy.sh
```

`deploy.sh` 会 `git pull --ff-only` 后重启 8060 服务并做健康检查。

首次把 5090 目录接成 checkout / 配 deploy key 的步骤，见部署纪律：deploy key 为**只读**，5090 不承担任何提交。

## 外部依赖（不随本仓分发）

本服务只包含应用代码，运行还需要 5090 上的以下外部资源：

1. **conda 环境**：`da3`（含 torch 等，是本服务的 python 运行时；环境名沿用历史称谓，DA3 模型本体已于 2026-08-25 退役，`/home/odyss/Depth-Anything-3` 源码与权重已从服务器删除）。
2. **电子秤硬件**（dx-backend / 8070 用，非 8060）：一台四通道称重变送模块 `SJ101T2_CH4_ETH`，需与 5090 在同一局域网可达（静态 `192.168.100.80`，Modbus TCP 502，通道 1..4 → 寄存器 addr 0/2/4/6）。网络前提见 [`NETWORK.md`](NETWORK.md)。

如需迁移到其他机器，`run.sh` 中的 conda python 路径需相应调整。
